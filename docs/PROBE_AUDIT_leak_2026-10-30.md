## 1. 怎么发现的

推进草案把 P2 的前提写成「VOID 率 × 籽通过」相图。核对归档时先看到异常：8 籽 × 5 次重复的 `leak_mean` **全部恰为 0.5**，`sd=0.0`、`se=0.0`。

一个真实测量不可能有 0 方差。顺着读 E2 实现（外部树 `code/s2c_env.py::obs_window_decode_acc`，**不在本包**）：

```python
for i, row in enumerate(traj):
    if row.get("cue_visible"):          # ① 跳过 cue 可见行
        continue
    ...
    if any(c.get("cue_visible") for c in chunk):   # ② 跳过含 cue 的窗口
        continue
    o = np.concatenate([c["obs"][WORLD_INP:] for c in chunk])   # ③ 只取 cue 块
```

而 `cue_vec()` 在 cue 不可见时**返回全零**。①②③ 合起来 ⇒ 特征矩阵恒为零。

## 2. 实测（`probe_v2.py`，hand_gate，N=2，chance=0.5）

| 配置 | n | 平衡准确率 | max\|X\| | 结构零 | 读法 |
|------|---|-----------|----------|--------|------|
| **E2 现状实现**（cue 块 + 跳过 cue 行 + 窗纯度） | 654 | **0.4709** | **0.000** | **是** | 等于类别先验，**不是测量** |
| **Dx2 权威口径**（全 obs 窗，允许窗内 cue 残留） | 741 | 0.7601 | 2.000 | 否 | 有信号（含行为通道，见 §4） |
| **阳性对照**（cue 全程可见） | 763 | **1.0000** | 1.000 | 否 | 探针**能**到天花板 |
| 修复版（cue 块 + 允许窗内残留） | 741 | 0.5256 | 1.000 | 否 | 弱信号，仅 cue 残留 |

**动态范围 = [0.5, 1.0]，可复现地上界 1.0。** 也就是说：探针本身能测，只是 E2 的取数方式让它永远读 0.5。

> 关于 `0.4709` 而非 `0.5`：`multinomial_decode_acc` 返回**普通准确率**，零特征时退化为类别先验。E2 八籽恰好 0.5，是因为那批标签平衡。两者是同一件事。

## 3. 与 Dx2 权威尺的对照

本包 `code/s1_env_s1.py::obs_window_decode_acc`（Dx2 权威尺）取的是**完整 obs 窗口**，且**不要求窗口纯净**：

```python
buf.append(obs.copy())
if (not cue_vis) and len(buf) == window:
    feat = np.concatenate(buf)      # 全 obs（28 维世界感知 + cue），允许窗内 cue 残留
```

Dx2 报告实测：籽均 leak **0.30–0.35**、sd 中位 ≈0.05、chance 0.25，且指出「泄漏基线来自窗内 cue 残留（结构）」。**它有方差、有结构基线 → 是有效探针。**

所以这不是「leak 尺子整体无效」，而是：**E2 移植时把尺子改坏了**——特征从全 obs 缩到 cue 块，又加了窗纯度过滤，两者叠加把信号清零。

## 4. 一个必须同时写明的混杂

Dx2 口径在本环境（S2c、N=2、hand_gate）给出 **0.7601**，远高于 Dx2 在 S1 环境的 0.30–0.35。原因是全 obs 窗口里含**行为痕迹**：agent 朝它认定的 valuable 资源移动，位置/资源布局就编码了目标。

这本身是**真实泄漏通道**（probe 不看 cue 也能读出目标），但它测的是「行为可推断性」，不是「cue 残留」。两者都算泄漏，**不可混为一谈**：

| 通道 | 含义 | 该由什么探针测 |
|------|------|----------------|
| cue 残留 | 窗内还有 cue 字面信息 | cue 块 + 允许窗内残留（修复版，0.5256） |
| 行为可推断 | 轨迹泄露目标 | 全 obs 窗口（Dx2 口径，0.7601） |

**建议**：两个都报，分别命名 `leak_cue_residue` 与 `leak_behavioral`，**禁止**合成一个数当 VOID 线。

## 5. 影响面

| 对象 | 影响 |
|------|------|
| E2 组门 **1/8 FAIL** | **不变**（VOID=0，分母 8，判决与探针无关） |
| E2 报告「VOID 种子 0/8；leak 线未削弱」 | 事实成立，但**不构成「无泄漏」的证据**——探针空转 |
| 「leak VOID 是历史组门阻滞器」 | **需重审**：Dx2 的 0.35 线基于有效探针（0.30–0.35 有方差），但 E2 起这条线在空转，**从未真正拦过任何籽** |
| P2（缺陷密度相图） | 原样不可执行（本文件即为原因）；须先修探针再谈 |
| 任何「E2 干净」措辞 | **撤回** |

## 6. 修法（三行代码级）

1. **恢复 Dx2 口径**：特征用完整 obs 窗口，去掉窗纯度过滤（保留「跳过 cue 可见行」以免直接把答案喂进去）。
2. **保留阳性对照作为硬闸**：每次跑 leak 前，先用 `cue_every=True` 的环境跑一遍，要求 ≥0.95；否则该跑的 leak 结果标 `PROBE_UNCALIBRATED`，不得进 VOID 判定。
3. **拆两个通道**：`leak_cue_residue`（cue 块）与 `leak_behavioral`（全 obs）分开报，各自定线。

实现见外部实验床 `percolation_lab/probe_v2.py`（`CONFIGS` 六种配置并列 + `audit()` + `leak_mean()`）。该文件**未收入本包**；本页不授权把修复后的探针拿去重跑 E2 或开 S3。

## 7. 可以怎么说 / 不可以怎么说

**可以**
- 「E2 版 leak 探针在实现上退化：特征恒零，对任何 agent 返回 chance。」
- 「因此 E2 的 VOID=0/8 不构成无泄漏证据；E2 的组门判决不受影响。」
- 「Dx2 权威尺有效（有方差、有结构基线）；问题出在 E2 的移植。」

- 「leak 尺子一直无效」（Dx2 版有效）
- 「E2 FAIL 因此翻案 / 应重跑」（判决与探针无关，且重跑需另开授权）
